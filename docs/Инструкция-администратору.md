# Y360 Admin — инструкция по сопровождению

Консоль администрирования Яндекс 360: синхронизация с Active Directory, архивация
ящиков уволенных, сроки хранения, восстановление почты.

## 1. Что где лежит

| Что | Где |
| :-- | :-- |
| Сервер | `ner-sdkr05`, 10.10.0.132, Ubuntu 24.04, PostgreSQL 16 |
| Код приложения | `/opt/y360-admin` (git-репозиторий, ветка `main`) |
| Виртуальное окружение | `/opt/y360-admin/venv` |
| Настройки (секреты) | `/opt/y360-admin/.env` (права `600`, владелец `ladmin`) |
| Пароль БД | `/home/ladmin/.y360_db_password` (права `600`) |
| Служба приложения | `/etc/systemd/system/y360-admin.service` |
| Публикация наружу | nginx, `/etc/nginx/sites-available/y360-admin` (TLS на 443) |
| Снимки ящиков | `/mnt/Mailbox/8365150/<логин>/<дата_время>/` + `.tar.gz` |
| Хранилище | NFS `10.10.1.18:/volume1/Mailbox` → `/mnt/Mailbox` (26 ТБ) |
| Резервная копия настроек сервера | `/home/ladmin/y360-backup-*.tgz` |

**Не трогать:** `/opt/yandex_audit`, `/opt/yandex_audit_logs`, службу
`yandex-audit.service` и сайт nginx `yandex-audit` (он слушает :80 как
default_server). Это отдельный сервис аудита.

## 2. Службы и их состояние

```bash
systemctl status y360-admin            # консоль
systemctl status nginx                 # публикация
systemctl status mnt-Mailbox.automount # монтирование хранилища
ss -ltn | grep -E ':443|:8080'         # порты: 443 наружу, 8080 только localhost
```

Ожидаемая картина: `y360-admin` — active, `nginx` — active, хранилище
смонтировано, консоль слушает только `127.0.0.1:8080` (наружу её отдаёт nginx).

## 3. Обычные операции

**Перезапуск консоли**
```bash
sudo systemctl restart y360-admin
journalctl -u y360-admin -n 20 --no-pager      # смотреть, что при старте
```

**Обновление кода**
```bash
cd /opt/y360-admin && sudo -u ladmin git pull
sudo systemctl restart y360-admin
```
Схема БД применяется автоматически при старте (`db/schema.sql`, идемпотентно).

**Проверка боевого контура** (безопасно: все шаги синхронизации в режиме dry-run)
```bash
cd /opt/y360-admin && ./venv/bin/python scripts/check_production.py
```

**Тесты**
```bash
./venv/bin/python tests/test_auth.py        # вход, группы, подпись токена
./venv/bin/python tests/test_services.py    # сервисы, хранилище, восстановление
./venv/bin/python tests/test_web_pages.py   # страницы
./venv/bin/python tests/test_filters.py     # исключения сервисных ящиков
```

**Снимок ящика вручную** (для уволенного, у которого нет архива)
```bash
./venv/bin/python scripts/resnapshot_users.py ivanov.i
# большой ящик — лучше в фоне:
nohup ./venv/bin/python scripts/resnapshot_users.py ivanov.i > /tmp/snap.log 2>&1 &
```

**Достроить снимок из уже выгруженного mbox** (когда архив не создался)
```bash
./venv/bin/python scripts/finalize_snapshot.py --list
./venv/bin/python scripts/finalize_snapshot.py --login ivanov.i --dry-run
./venv/bin/python scripts/finalize_snapshot.py --login ivanov.i
```
Скрипт откажется достраивать, если mbox оборван или заметно меньше размера из БД.

**Убрать мусор от прерванных снимков** (сначала без `--yes` — только показывает)
```bash
./venv/bin/python scripts/cleanup_incomplete_snapshots.py
./venv/bin/python scripts/cleanup_incomplete_snapshots.py --yes
```
Удаляет только каталоги, для которых у того же логина уже есть готовый снимок.

**Обновить сроки хранения** (правится файл, потом загрузка)
```bash
nano /opt/y360-admin/db/retention_positions.txt   # формат: <срок>TAB<должность>
./venv/bin/python scripts/load_retention_positions.py
```

**Восстановление ящика** — через веб-интерфейс: раздел «Восстановление» →
выбрать сотрудника и снимок → выгрузить ящик целиком или отдельные письма.

## 4. Вход и права

- Вход через ADFS (OIDC), режим задаётся в `.env`: `AUTH_MODE=oidc`
  (`none` — без входа, `ldap` — вход логином и паролем домена).
- Права — по группе `GLB-Yandex360-Admin-GRP`. Группы берутся **из Active
  Directory по LDAP**: ADFS не кладёт группы в токен (в id_token их нет, а
  access-токен выдаётся непрозрачным, потому что у Web API в ADFS не
  сгенерирован ключ подписи JWT). При желании это можно включить в ADFS, но
  текущая схема работает без правок на его стороне.
- Сертификат: `*.kolmar.local` от внутреннего CA `Kolmar Root CA`
  (отпечаток SHA256 `8F:33:1B:D4:23:40:7C:CE:77:34:BD:1F:8F:93:B1:6F:16:8E:1B:EE:DB:BE:28:DE:E4:29:E6:34:14:3D:06:48`).
  Корень должен быть раскатан в «Доверенные корневые центры» политикой домена,
  иначе браузеры не сохраняют куки и вход не работает.

## 5. Если что-то не работает

**Не открывается адрес** — проверьте `systemctl status y360-admin nginx` и
`ss -ltn`. Если служба «inactive» — посмотрите журнал: частая причина в том,
что отмонтировалось хранилище (у службы есть зависимость «не работать без
`/mnt/Mailbox`»).

**«state не совпал» при входе** — браузер не сохранил куку входа. Причины:
не доверенный сертификат, Internet Explorer, вход по прямому адресу с портом
8080. Смотрите журнал: там пишется адрес запроса и наличие куки.

**«Доступ запрещён: нет членства в группе»** — проверьте членство в AD:
```bash
cd /opt/y360-admin && ./venv/bin/python -c "
import sys; sys.path.insert(0,'.')
from web import auth
print(auth.ldap_groups_of('kuznetsov@kolmar.local'))"
```

**Хранилище не смонтировано** — `sudo systemctl start mnt-Mailbox.automount`,
затем `findmnt /mnt/Mailbox`. Строка в `/etc/fstab`:
```
10.10.1.18:/volume1/Mailbox /mnt/Mailbox nfs _netdev,x-systemd.automount,x-systemd.mount-timeout=30,noauto 0 0
```
⚠️ **`x-systemd.idle-timeout` добавлять нельзя.** Однажды это уже привело к
остановке консоли: через 10 минут простоя NFS отмонтировался, а из-за
`RequiresMountsFor=/mnt/Mailbox` systemd корректно остановил службу — со
стороны это выглядело как «сервис упал».

**Диагностика снимков и кандидатов**
```bash
./venv/bin/python scripts/diagnose_incomplete.py   # незавершённые каталоги + сверка с AD
```

## 6. Переключение и откат (легаси-сервисы)

Старые интерфейсы (только на время перехода):
```bash
systemctl status yandex-sync                # Streamlit, порт 8501
systemctl status yandex-mailbox-streamlit   # Streamlit, порт 8502
```

Переключение (в согласованное окно):
```bash
sudo systemctl stop yandex-sync yandex-mailbox-streamlit
sudo systemctl mask yandex-sync yandex-mailbox-streamlit
```

Откат (если что-то пошло не так):
```bash
sudo systemctl unmask yandex-sync yandex-mailbox-streamlit
sudo systemctl start yandex-sync yandex-mailbox-streamlit
```

`yandex-audit` при переключении не трогаем: это отдельный сервис, он продолжает
работать на порту 80.

## 7. Настройки в .env (ключевое)

```ini
AUTH_MODE=oidc
SESSION_SECRET=<32 байта hex>              # не менять: иначе все разлогинятся
OIDC_ISSUER=https://sso.kolmar.ru/adfs
OIDC_CLIENT_ID=https://y360-admin.kolmar.local    # в этом ADFS это Identifier
OIDC_CLIENT_SECRET=<секрет из ADFS>
OIDC_REDIRECT_URI=https://y360-admin.kolmar.local/oauth2/callback
OIDC_ADMIN_GROUP=GLB-Yandex360-Admin-GRP
OIDC_GROUP_CLAIM=group
OIDC_AUDIENCE=https://y360-admin.kolmar.local
AUTH_COOKIE_SECURE=1
UI_HOST=127.0.0.1
UI_PORT=8080
BACKUP_ROOT=/mnt/Mailbox
ARCHIVE_EXCLUDE_LOGINS=kolmar-id-360,yndx-forms-cnt-robot
```

Сервисные (роботные) ящики в архивацию не берутся: роботы определяются по
признаку `isRobot` в Яндекс 360, плюс работает список исключений выше.
